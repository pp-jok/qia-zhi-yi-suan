# v0.8.1 深层语义综合根因与最小整改

## 根因

`AuditedCrossSystemAlignment` 描述同一 topic 的证据关系，不是人格互动机制。v0.8.0 把 `tension`、`validation`、`unresolved` 全部转换为 Dynamic，随后将前三个 Signature 转为 Shadow/Mature、前四个转为 Theme，并总是产生 Archetype。这违反了“证据不足即不形成”的边界。

## 最小方案

保留 `audited-interpretive-cdp-v1` 的独立产品身份，不读 candidate mapping，也不改 formal primitive CDP。扩展产品 item 的派生元数据，并采用以下闭环：

1. Signature 只保留 cross-system validation 或单一候选中有两个以上方向且有独立 mechanism 的结构；其他候选仍为 supporting observations。
2. Dynamic 只从一个候选内明确的多方向、多 mechanism 序列形成，或从有共享 activation context 的两条独立 signature 形成；alignment 单独存在不升级。
3. Shadow/Mature 只由 Dynamic 的具体 relationship type 和其 pole mechanism 受控推导，标为 hypothesis。
4. Theme 至少要求两个不同 Dynamic 复现同一 context/机制轴；不足则为空。
5. Archetype 至少要求一个 Theme 加两个 Dynamic；不足则为空。
6. Planner 以实际可用层级选择章节，允许 1–7 节；Renderer 从结构字段组织叙事，不再直接拼接 statement。

这会使部分完整命盘仍输出较短报告。那是现有规则覆盖的真实边界，而不是产品失败或需要用通用话术填补的空洞。
