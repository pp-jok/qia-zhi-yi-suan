# qia-zhi-yi-suan v0.8.0

## Core Profile Product

`build-birth-report` now defaults to `core-profile-v1`. It writes the user report plus `facts.json`, `qualification.json`, `core_profile.json`, `report_plan.json`, `report_audit.json`, and `execution.json`.

The new `audited-interpretive-cdp-v1` is built from qualified local calculation facts and the packaged, versioned interpretive rule bundle. It records bazi and astrology candidates, exact-topic cross-system relationships, signatures, dynamics, reflective shadow/mature expressions, themes and an archetype index.

The report planner selects 4–8 sections from the actual profile and binds every section to an evidence fingerprint. The renderer does not read raw facts, rules or candidate registries.

## Boundaries and compatibility

This is not formal primitive semantic coverage. The existing `core-destiny-profile-v1` remains limited-coverage unknown-only, and no candidate mapping is promoted or read by the new product route.

`standard-interpretive-v1` and `concise-interpretive-v1` remain available as explicit compatibility modes. The calculation method remains local tropical whole-sign astrology with recorded provider provenance and independent qualification.
