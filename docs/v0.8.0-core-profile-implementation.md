# v0.8.0 Core Profile 实施说明

实现使用独立的 `audited-interpretive-cdp-v1` 产品 IR，而不改变 `core-destiny-profile-v1` 的 formal release 语义。其保证如下：

- `semantic_model_assurance` 固定为 `audited_interpretive_rule_derived`；
- 内容仅来自 `qualified facts` 触发的 versioned interpretive rules 与现有 cross-system synthesis；
- 每个可读章节都记录 CDP 条目、signal id、rule ref 与限制；
- report planner 按实际 evidence 选择 4–8 个章节，无证据不输出；
- 默认出生入口使用 `core-profile-v1`，两个旧模式完整保留。

落盘 artifacts：`facts.json`、`qualification.json`、`core_profile.json`、`report_plan.json`、`report_audit.json` 与用户报告 JSON。生成报告不读取 candidate asset，也不写 release manifest。
