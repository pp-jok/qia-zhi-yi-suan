# C2 Semantic Mechanism Candidates

## Registry status

```text
Bazi semantic mechanisms admitted: 0
Astrology semantic mechanisms admitted: 0
Fresh Primary Mapping Candidates admitted: 0
```

No Candidate Mechanism Card is admitted because the project currently supplies deterministic fact structures but no project-owned semantic mechanism that can answer a C1 Primitive semantic question without reproducing a rejected legacy shortcut. This is a design result, not a permanent prohibition on any fact family.

## Bazi fact-family assessment

| Canonical fact family | Available deterministic fields | Primary mechanism status | Role eligibility without a Primary mechanism | Reason |
|---|---|---|---|---|
| Day Master and month environment | day stem, month branch, deterministic element/season table | `NO_CURRENT_DEFENSIBLE_MAPPING` | descriptive audit context only | Existing table explicitly excludes strength, favorable elements, patterns, and outcomes; no mechanism answers a Primitive question. |
| Ten Gods | subject reference, Ten-God category, source pillars, visible/hidden kind | `NO_CURRENT_DEFENSIBLE_MAPPING` | component of a future compound rule only | Single-Ten-God shortcuts are prohibited; no approved compound mechanism distinguishes the C1 neighbor boundaries. |
| Pillar position and provenance | year/month/day/hour, visible/hidden source | `NO_CURRENT_DEFENSIBLE_MAPPING` | `RULE_GATE` or provenance constraint only | Position/provenance establishes availability and scope, not Primitive direction. |
| Relations | relation type, participant references, source pillars | `NO_CURRENT_DEFENSIBLE_MAPPING` | component of a future compound rule only | Deterministic relation facts have no project-owned bridge to judgement, preference, response, action, affect regulation, or organization. |
| Hour-pillar facts | time-sensitive pillar, hidden stems, Ten-God/relationship sources | `NO_CURRENT_DEFENSIBLE_MAPPING` | time-scope `RULE_GATE` only | Time sensitivity controls availability; it does not supply personality meaning. |

## Astrology fact-family assessment

| Canonical fact family | Available deterministic fields | Primary mechanism status | Role eligibility without a Primary mechanism | Reason |
|---|---|---|---|---|
| Planetary placements and signs | body, longitude, sign, degree | `NO_CURRENT_DEFENSIBLE_MAPPING` | component of a future compound rule only | Planet/sign labels are not automatic Primitive direction. |
| Aspects | body pair, aspect type, orb | `NO_CURRENT_DEFENSIBLE_MAPPING` | `RULE_GATE` or `MODIFIER` attached to Primary Evidence | Aspect is not Primitive direction; no primary mechanism exists to modify. |
| Dignity | body, dignity type | `NO_CURRENT_DEFENSIBLE_MAPPING` | `MODIFIER` only | Runtime methodology already fixes dignity as modifier-only. |
| Houses, angles, MC, Ascendant | house, cusp, Ascendant, MC, angle aspects | `NO_CURRENT_DEFENSIBLE_MAPPING` | time-sensitive `CONTEXTUALIZER` or salience modifier only | They are scope/salience facts, not direction; they require known time. |
| Orb bands | deterministic aspect orb | `NO_CURRENT_DEFENSIBLE_MAPPING` | strength modifier only | Orb can qualify expression salience but cannot establish a Primitive mechanism or direction. |

## Candidate-card admission protocol

Any future card must include `mechanism_id`, `source_system`, canonical requirements, semantic description, target Primitive/question, role, direction, allowed contexts, global eligibility, modifiers, counter-conditions, exclusions, root strategy, time scope, limitations, alternative interpretations, collision risk, and status. Until all fields are supported by project-owned assets, no card enters this registry.

## Explicit non-admissions

The following are intentionally not mechanism candidates: `比肩 = P001`, `伤官 = P004`, `正官 = P006`, `正印 = P002`, `Mars = P004`, `Saturn = P006`, `Moon = P003`, `square = low`, and `trine = high`. These examples are rejected shortcut forms, not bans on the underlying canonical facts.
