# 项目自有事实溯源与受限修饰设计

**状态：** 待规格审阅  
**范围：** 解除 Core Profile 候选提升门中可由项目内确定性资产解决的四项事实缺口。

## 目标

使 Core Profile 候选映射能够审计以下已有或可机械推导的事实，而不调用外部服务、不采用未版本化的通用表、也不让解释层补造事实：

1. 八字 Ten-God 的显干 / 藏干来源。
2. 日主与月令构成的日主环境事实。
3. 西占尊贵度对已激活规则的限定作用。
4. 已知出生时间下的角宫 / 宫位上下文对已激活规则的限定作用。

## 决策与边界

### 八字

在 `TenGodFact` 增加必填枚举来源：`visible_stem` 或 `hidden_stem`。旧事实包可以在通用事实校验中保留 `unknown`，但候选 Core Profile 映射不得把 `unknown` 当作可用来源。

新增不可变 `DayMasterEnvironmentFact`，记录：日干、日干五行、月支、季节分类、来源柱位和版本化项目表引用。它只能由日柱天干与月柱地支通过项目自有 `bazi_day_master_environment_v1.yaml` 机械推导；不包含旺衰、喜忌、格局或强弱判断。

每条八字候选映射必须同时满足：两类 Ten-God 证据、至少两个独立柱位、允许的来源类型，以及日主环境存在。若环境缺失，规则不激活并留下限制。

### 西占

不新增天体或相位计算。复用已验证的 `DignityFact`、行星落宫、Ascendant、MC、House Cusp。

尊贵度、角宫和宫位只能作为已经由主要相位激活的候选规则的修饰/上下文；它们不能单独生成 Primitive、改变方向或提高系统外证据权重。未知出生时间继续排除全部角宫与宫位条件。

候选映射 DSL 新增受限字段：`dignity_modifier_any`、`angular_body_any`、`house_context_any`。每个字段均为可选强化条件；没有主要相位激活时无效。

## 数据流

```text
版本化八字环境表 + 已验证命盘柱位
→ DayMasterEnvironmentFact
→ 来源明确的 TenGodFact
→ 八字候选 Primitive

已验证相位 + DignityFact + 已知出生时间的宫位/角宫事实
→ 受限西占候选 Primitive
→ 独立状态、对齐、候选 Report Plan
```

所有新事实与映射引用均进入 Profile 审计字段和 Bundle 指纹。任何项目表或候选规则变化均使 C4b 指纹失效，必须重跑设计/校准集。

## 提升门

`validate_candidate_bundle_for_promotion()` 将逐项删除已实现且有测试的阻断码；其余未满足条件继续阻断。候选资产始终不进入默认路由或生产 `configs/`，直到全部提升门及后续 Holdout 验证通过。

## 错误处理

- 来源未知、环境事实缺失、相位不符合、未知出生时间需要宫位：规则不激活，输出限制；不得猜测。
- 配置版本、枚举值或引用不一致：返回稳定错误码并停止候选提升。
- 尊贵度/角宫/宫位试图独立激活 Primitive：候选配置校验失败。

## 测试策略

1. 先写失败测试，分别覆盖显/藏来源、环境缺失、环境机械推导、尊贵度修饰、角宫/宫位已知时间保护与独立激活禁止。
2. 校验候选映射仍保持八字/西占来源隔离，`unknown` 不降格为低值。
3. 重跑 8 个 Design Set，确认指纹失效/重绑定、确定性和相似度阈值行为。
4. 通过提升门测试证明只有已完成的阻断码被移除。

## 非目标

- 不实现旺衰、喜忌、格局、流年或大运。
- 不补充外部排盘 Provider。
- 不新增默认 Dynamic、Fate Theme、Archetype 或用户可见报告文案。
- 不访问 Holdout Set，不进行生产发布。
